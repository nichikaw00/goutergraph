# プロダクト概要

- 状態: Active
- 最終確認日: 2026-10-04
- 正本の対象: プロダクトの目的、価値、設計原則、非目標

## 一文で表すと

コーヒー・紅茶・スイーツの商品情報と写真を保存し、繰り返した体験や自分の感覚を追記できる個人アーカイブ。後から見返し、比較して学び、人に体験を伝えられるようにする。

## 背景と解決したい問題

ユーザーは、商品名、産地、品種、焙煎度、店員の説明、パッケージやカードといった情報を、記憶から失われる前に残したい。コーヒーや紅茶について学ぶ過程では、専門家の表現を実際の香りや味と照らし合わせ、同じ商品を異なる条件で体験した結果も蓄積したい。

既存の記憶だけでは、時間が経つと商品名や場所、特徴が抜け落ちる。入力項目が多すぎる記録方法は、その場での保存を妨げる。そこで、商品情報の保存と、体験・感覚の追記を別のタイミングで行えることが重要になる。

## 主な利用者

初期の利用者はプロダクト所有者本人である。MVP は単一ユーザーの個人アーカイブとして価値を検証し、一般ユーザー向けの登録・利用を前提にしない。将来の複数ユーザー対応は否定しないが、初期実装へ含めない。

## 主要な利用場面

MVP の中心シナリオは、次の一連の流れとする。

> 商品を購入・発見した直後に、写真と分かる範囲の商品情報を素早く保存する。その後、自宅や店舗で味わうたびに、同じ商品へ体験を追記する。

この中心シナリオに関連して、次の場面での利用を想定する。これらはプロダクトが支える利用文脈であり、すべての機能を同時に MVP へ含めることを意味しない。

### 記録する

- カフェでおいしいコーヒーを飲んだとき、忘れないうちに写真と店だけでも保存する。
- コーヒー豆を買ったとき、パッケージやカードを撮り、後から詳細を見返せるようにする。

### 再発見する

- ケーキを食べた数か月後、友人からおすすめを聞かれたとき、自分の記録から東京でおいしかったケーキ店を探す。
- 以前飲んだ紅茶の商品名を思い出せないとき、写真、場所、時期などの曖昧な手がかりから見つける。

### 伝える

- 誰かにおすすめするとき、商品名だけでなく、どこで飲食したか、どう感じたかという自分の体験とともに伝える。

記録する場面を最初の価値検証対象とし、再発見は記録の蓄積後に検証する。初期の「伝える」は、自分の記録を見返して口頭で紹介する利用場面を指す。

アプリ内の共有機能は保留とし、MVP には含めない。他ユーザーへサービスを展開するフェーズ、または第三者がこの Web アプリのページを閲覧できる形を検討するフェーズで、共有の単位、方法、公開範囲を再検討する。

## 将来の UI 方向性

現時点では、次の画面構成と視覚的な区別を検討している。これは方向性の仮説であり、情報設計やユーザビリティの検証前に具体的な画面数や配色を固定しない。

- コーヒーの記録を確認・修正する画面
- 紅茶の記録を確認・修正する画面
- スイーツの記録を確認・修正する画面
- 新しく記録する画面
- 各カテゴリまたは画面に、それぞれを識別しやすい色味を持たせる

色はカテゴリを理解する補助として使い、ラベル、見出し、アイコンなどを併用して、色だけが識別手段にならないようにする。

## 提供形態

MVP はスマートフォンを第一対象としたレスポンシブ Web アプリとして提供し、PWA としてホーム画面へ追加できるようにする。現場ではスマートフォンから写真撮影と素早い記録を行い、PC ブラウザからは詳細の確認・修正にも利用できるようにする。

初期段階では App Store／Google Play での配布を行わない。ネイティブアプリ固有の能力が価値検証に必要だと判明した場合に、改めて提供形態を見直す。

## 価値の優先順位

1. **記憶**: 商品を特徴づける情報、写真、場所を失わず、後から見つけられる。
2. **学習**: 商品に複数の体験を重ね、外部の説明と自分の感覚を比較できる。
3. **紹介**: 必要なときに記録を見返し、自分の体験を他者へ口頭で伝えられる。

記録対象の中心は **Product（商品）** である。Experience（体験）は商品に従属して複数追加される。自分の感覚は有益だが、商品情報より優先度が低い。

## プロダクト原則

### 1. 商品を主役にする

商品登録と体験記録を分離し、同じ商品へ複数回の体験を追加できるようにする。

### 2. 写真を一次情報として扱う

パッケージ、裏面、商品カード、店頭説明などは単なる装飾ではない。文字情報だけでは失われる文脈を保持する商品資料である。

### 3. 軽い記録と深い記録を両立する

不明な項目があっても保存でき、分かった情報を後から補えるようにする。詳しく観察したい回だけ、感覚や抽出条件を追加できるようにする。

### 4. 事実・外部説明・自分の感覚を混同しない

商品属性、店員やカードによる説明、自分が感じたことを区別して保持する。プロダクトは味覚の「正解」を断定せず、過去の体験との比較を助ける。

### 5. 曖昧な記憶から再発見できるようにする

名前だけでなく、写真、時期、場所、カテゴリ、商品属性など、複数の手がかりから過去の記録へ辿れることを重視する。

## 現時点の非目標

- 商品・体験の公開 URL 発行や、画像・テキストを他アプリへ送る共有機能
- 公開フォロー、フィード、反応数を中心とした SNS を作ること
- 味や香りの感じ方に唯一の正解を与えること
- 初期段階から嗜好を自動分析・推薦すること
- 最初から百科事典のような外部知識ベースを構築すること
- すべてのカテゴリや入力項目を同じ構造へ無理に統一すること

これらは将来の可能性を否定するものではないが、ユーザー検証なしに初期スコープへ含めない。

## 成功を判断する観点

定量目標は未決定。初期検証では次を観察する。

- 実際の利用場面で、記録を途中放棄せず保存できるか。
- 数週間・数か月後に、曖昧な手がかりから目的の商品を見つけられるか。
- 同じ商品へ無理なく体験を追記できるか。
- 商品の事実、外部の説明、自分の感覚を見分けて振り返れるか。
- 蓄積した記録が、学習や人への紹介に実際に使われるか。
